# 문서 리뷰 기준 연구 노트 (2026-08)

`rubrics/doc.md` 갱신의 근거 기록입니다. WebSearch 기반 조사 (공식 가이드 · 측정 연구 · 업계 관행 구분 표기).

## 핵심 실측 수치

| 수치 | 출처 |
|---|---|
| 독자의 79%는 스캔만 함, 정독은 16% | NN/g 사용자 테스트 (1997) |
| 평균 페이지뷰 시간에 읽히는 분량은 단어의 20~28% | NN/g 시선추적·로그 분석 |
| 간결하게 쓰면 사용성 +58%, 스캔 가능하게 +47%, 결합 시 +124% | NN/g 웹 글쓰기 실험 |
| 플레인랭귀지 메모 → 읽기 시간 17~23% 단축 | 미 해군 실험 (Kimble 집대성) |
| 안내문 1통 개선 → 문의 전화 1,100건 → 200건 미만 | 미 보훈부 사례 (Kimble 인용) |
| 문장 평균 8단어 → 이해도 100%, 43단어 → 10% 미만 | American Press Institute (2차 인용, 근거 강도 중간) |
| Amazon: 2004년 임원회의 PPT 금지, 회의 첫 20~30분은 6-pager 침묵 독해 | Bezos 사내 메일, CNBC 보도 |

정직한 한계: "임원은 요약만 읽는다"를 정량 측정한 전용 연구는 확인하지 못함 — NN/g 스캐닝
데이터와 Amazon 관행이 간접 근거.

## 반영한 프레임워크

- **BLUF** (Bottom Line Up Front) — 미 육군 공문 규정 AR 25-50이 명시 요구. 결론+목적을 서두에
- **Minto 피라미드** — 답 먼저, 주장 바로 아래 근거(수직 Q&A), MECE, SCQA 도입부
- **Amazon 내러티브** — 6-pager(본문 서술 + 데이터는 부록), PR-FAQ(임원의 반문에 미리 답하기)
- **Plain Writing Act 2010** — 특정 독자에 맞춘 작성은 미 연방 법적 요구사항
- **결정 메모 관행** — 단일 결정권자, "누가·무엇을·언제까지" 한 문장, 대안 2~3개+기각 사유
- **NN/g 역피라미드·frontloading** — 제목·문단·문장 모두 앞부분에 핵심

## rubric에 반영한 변경

1. ①번에 제목까지 포함 (스캔 독자는 제목+첫 줄만 읽음)
2. ②번에 수직 Q&A, 대안 비교, 예상 반문 대응, 데이터 부록 분리 추가
3. ③번에 단일 결정권자 특정, SCQA 도입 추가
4. ④번에 실명 owner + 확정 기한, 문서 목적 자기 선언 추가
5. **공통 감점 신설**: 문장 부담 (최대 -10) — 5번째 축 대신 감점제 (연구 권고안 그대로)
6. 문서 유형별 무게중심 안내 (공지=행동 중심, 보고서=결론·근거 중심)
