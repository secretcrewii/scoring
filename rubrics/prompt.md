# 프롬프트 채점 기준

이 파일이 채점 기준의 **단일 출처**입니다. 기준을 바꾸고 싶으면 이 파일만 고치면 됩니다.
코드는 건드리지 않아도 됩니다.

> 이 기준은 2026-08 프롬프팅 연구 조사(공식 문서 3사 + 학술 측정 연구 + 실무 사례, 89건)를
> 반영해 갱신되었습니다. 근거와 출처는 [docs/research/prompting-research-2026-08.md](../docs/research/prompting-research-2026-08.md) 참고.
> 참고로 이 4개 항목 구조는 Google 공식 PTCF(Persona·Task·Context·Format) 프레임워크와 거의 일치합니다.

## 설정

아래 블록의 숫자만 바꾸면 훅의 동작이 바뀝니다.

- `threshold` — 이 점수 미만일 때만 코칭 노트가 뜹니다. 올리면 더 자주 뜨고, 내리면 덜 뜹니다.
- `weights` — 항목별 배점. 합이 100이 되게 유지하세요.

```json
{
  "threshold": 75,
  "weights": {
    "role": 25,
    "context": 25,
    "format": 25,
    "constraint": 25
  }
}
```

## 채점 항목

### 1. 역할 부여 (role) — 25점

AI에게 **누구로서, 어떤 관점으로** 답할지 지정했는가.

**채점 철학**: 역할은 정확도 장치가 아니라 **말투·관점·눈높이 장치**입니다.
전문가 페르소나가 사실형 과제의 정답률을 높이지 못한다는 대규모 측정 결과
(EMNLP 2024 · Wharton Report 4)가 있으므로, "역할이 있는가"가 아니라
"역할이 톤·독자·시각에 맞게 구체적인가"로 채점합니다.

| 점수 | 상태 |
|---|---|
| 22~25 | 분야+연차+독자까지 구체적 ("여성 패션 이커머스 10년차 CRM 마케터로서, 휴면 고객에게") — **또는** 역할 없이 독자·용도·관점을 동등하게 구체적으로 지정 ("30대 육아맘 고객에게 보낼 재구매 유도 문자입니다") |
| 15~21 | 역할은 줬으나 뭉뚱그려짐 ("너는 마케터야") |
| 8~14 | 분야만 언급 ("마케팅 관련해서") |
| 0~7 | 역할도, 독자·관점 지정도 없음 |

**감점 사유**

- 역할이 과업과 무관함 (코드 리뷰를 시키면서 "너는 시인이야")
- 낮은 지식 페르소나 ("초보자라고 생각하고 답해줘") — 답 품질을 실제로 떨어뜨린다는 측정 결과가 있음.
  눈높이 조절이 목적이면 출력 기준("초보 셀러도 이해하게 설명해줘")으로 바꾸도록 안내
- 역할을 여러 개 겹쳐 지정해 초점이 흐려짐

**만점 인정 특례**: 사실 확인·계산 작업에서 역할 대신 검증 관점을 직접 지정한 경우
("부가세 누락 리스크 관점에서만 검토") — 측정상 이쪽이 더 안전한 사용법입니다.

### 2. 맥락 · 배경 (context) — 25점

**왜** 이 작업이 필요하고, **누가** 결과를 볼 것이며, **필요한 자료**를 줬는가.

**채점 철학**: 맥락은 **양이 아니라 관련성**으로 채점합니다. 무관한 배경 정보가 섞이면
잘 풀던 문제도 틀린다는 측정 결과(ICML 2023)가 있습니다.

| 점수 | 상태 |
|---|---|
| 22~25 | 목적 + 대상 독자 + 필요 자료가 모두 있고, 무관한 정보가 없음 |
| 15~21 | 목적은 있으나 대상이나 자료가 빠짐 |
| 8~14 | 배경 한 줄 정도 |
| 0~7 | 맥락 없이 지시만 |

**가점 요소**

- 지시에 '왜'가 붙어 있음 — "음성 안내로 나가니 말줄임표 금지" (Anthropic 공식 권장 형태)
- 긴 자료를 위에, 질문·지시를 맨 아래 배치 (Anthropic 실측 최대 30% 개선)
- 근거 자료 고정 — "아래 약관에 근거해서만 답하세요" (환각을 측정상 줄임)
- AI가 안다고 가정하지 않고 실제 자료(기존 문구·정책 원문·데이터)를 직접 제공

**감점 사유**

- 무관한 배경 정보 나열 (회사 연혁 등 — 정확도를 실측으로 떨어뜨림)
- AI가 알 수 없는 내부 약어·고유명사를 설명 없이 씀
- "그거", "저번에 그거" 처럼 지시 대상이 불명확함
- 고객 실명·연락처 등 개인정보 원문 포함 — 세그먼트 표현("30대 재구매 고객")으로 바꾸도록 안내

### 3. 출력 형식 (format) — 25점

**어떤 모양으로** 답할지 정해줬는가. 슬롯 4개를 봅니다: **구조 + 분량(숫자) + 말투 + 예시**.

**채점 철학**: 형식을 잡는 최강 수단은 설명이 아니라 **예시**입니다 (3사 공통 권장).
한국어에서는 **출력 말투 지정**(해요체/합쇼체/반말)이 특히 중요합니다 — 모델이 스스로 맞히지 못합니다.

| 점수 | 상태 |
|---|---|
| 22~25 | 잘 나온 예시 첨부, **또는** 구조+분량(숫자)+말투를 모두 지정 |
| 15~21 | 구조·분량·말투 중 한두 가지만 있음 |
| 8~14 | "간단히", "자세히" 같은 모호한 지시만 |
| 0~7 | 형식 지시 없음 |

**감점 사유**

- 형식 지시가 서로 충돌함 ("표로, 그리고 줄글로")
- 분량이 과업에 비해 비현실적임

**감점하지 않는 것** (팁으로만 안내)

- 짧은 프롬프트에 구분 태그(`<자료>`, `##`)가 없는 것 — 최신 모델에선 불필요
- 복잡한 분석에 엄격한 형식을 처음부터 강제한 것 — "자유 분석 → 형식 정리" 2단계 패턴을 개선안으로 제시

### 4. 제약 · 예외 (constraint) — 25점

**지켜야 할 선**을 그어줬는가. **개수가 아니라 정밀도**로 채점합니다.

**채점 철학**: 핵심 제약 5개 안팎이 이상적입니다. 규칙 나열이 길수록 중요한 규칙이 묻히고,
모델은 부정형 지시("~하지 마")를 체계적으로 무시하는 경향이 있습니다 (negation blindness).

| 점수 | 상태 |
|---|---|
| 22~25 | 핵심 제약이 정밀함: 금지+대체 행동 짝 ("할인 언급 대신 품질 강조") + 예외 처리 지침 ("자료에 없으면 [확인 필요]") 또는 탈출구 ("모르면 모른다고 답해") |
| 15~21 | 한두 가지 유효한 제약 (부정형만 나열해도 여기까지) |
| 8~14 | 제약을 암시만 함 |
| 0~7 | 제약 없음 |

**가점 요소**

- "모르면 모른다고 답하세요" 류의 탈출구 — Anthropic 공식 환각 방지 1순위 전략
- 지시 충돌 시 우선순위 명시 ("두 규칙이 충돌하면 재고 안내를 우선")
- 기준이 있는 자가 점검 지시 ("30자 이내·금지어 없음 2가지 기준으로 스스로 점검한 결과 첨부")

**감점 사유**

- 서로 모순되는 지시 — 최신 모델일수록 성능을 크게 해침 (OpenAI 공식 경고)
- "반드시!! 절대!!" 강조 남발 — 최신 모델에서 과잉 반응 유발 (Anthropic 공식)
- 제약이 너무 많아 답할 수 있는 공간이 없음

## 점수대별 총평

| 총점 | 서술 |
|---|---|
| 90~100 | 그대로 재사용할 만한 프롬프트. 팀 자산으로 저장할 가치가 있음 |
| 80~89 | 잘 썼음. 한 항목만 다듬으면 90점대 |
| 70~79 | 쓸 만하지만 AI가 한 번은 되물을 수준 |
| 60~69 | 결과를 받고 나서 다시 시킬 확률이 높음 |
| 60 미만 | 지시라기보다 질문에 가까움. 다시 쓰는 편이 빠름 |

## 채점할 때의 태도

- **잘한 것을 먼저 말합니다.** 60점짜리에도 잘한 구석은 있습니다.
- **한 번에 한 가지만 고치게 합니다.** 네 항목을 다 지적하면 아무것도 안 고칩니다.
- **고쳐 쓴 프롬프트 전문을 보여줍니다.** 설명만으로는 무엇을 어떻게 바꿔야 할지 다시 번역해야 합니다.
- **가장 흔한 실패는 기법 부족이 아니라 짧은 프롬프트입니다.** 성과 좋은 프롬프트는 평균 21단어,
  보통의 첫 프롬프트는 9단어 미만입니다 (Google 측정). 화려한 기법보다 "두세 문장 더 구체화"를 1순위로 권하세요.
- **측정된 근거가 있는 것만 권합니다.** 감정 호소("중요한 일이야"), 팁 제안, 공손한 말투는
  측정상 품질과 무관합니다 — 가점도 감점도 하지 않습니다.
- 점수는 낙인이 아니라 **다음 한 걸음의 방향 표시**입니다.
