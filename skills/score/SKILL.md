# 프롬프트 채점

사용자(주로 대표)가 쓴 프롬프트를 정독하고 점수·근거·팁을 냅니다.
훅의 자동 점수는 키워드 기반의 얕은 감지입니다. 여기서는 **실제로 읽고 판단합니다.**

## 절차

1. **채점 대상 확보**
   - 인자로 텍스트가 주어졌으면 그것을 채점합니다.
   - 비어 있으면 **직전 사용자 프롬프트**(이 명령어 바로 앞의 발화)를 채점합니다.
   - 직전 프롬프트도 찾을 수 없으면 "어떤 프롬프트를 볼까요?"라고 한 줄로 묻고 멈춥니다.

2. **기준 읽기** — `${CLAUDE_PLUGIN_ROOT}/rubrics/prompt.md`를 Read로 읽습니다.
   여기 적힌 항목별 점수표와 감점 사유가 유일한 채점 기준입니다. 임의로 기준을 만들지 마세요.

3. **팁 읽기** — `${CLAUDE_PLUGIN_ROOT}/rubrics/tips.md`를 Read로 읽고,
   점수가 낮은 항목에 해당하는 팁을 골라 씁니다.

4. **채점** — 네 항목(역할 부여 / 맥락·배경 / 출력 형식 / 제약·예외)에 각 25점을 배점합니다.
   점수마다 **그 프롬프트의 실제 문구를 인용해** 근거를 답니다. 일반론으로 때우지 마세요.

   그다음 `prompt.md`의 **공통 감점(과업 명확성, 최대 -15)** 을 적용합니다. 감점이 있으면
   출력의 총점 줄 옆에 사유를 한 줄로 밝히세요 — 예: `종합 51점 (과업 명확성 -10)`.
   감점 후 60점 미만이면 항목별 조언보다 "무엇을 시킬 건지 한 문장으로 먼저 정하기"를 앞세웁니다.

5. **출력** — 아래 형식을 그대로 씁니다.

6. **기록** — 채점이 끝나면 Bash로 기록합니다.
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/ledger-write.js" --kind prompt --source skill --total <총점> --role <점수> --context <점수> --format <점수> --constraint <점수> --len <원문 길이>
   ```
   기록 실패는 무시하고 진행합니다. 사용자에게 알리지 않습니다.

## 출력 형식

```
종합 78점 (B)
──────────────────────────────
역할 부여    ████████░░  20/25
맥락 · 배경  ████████░░  20/25
출력 형식    ████░░░░░░  10/25  ← 제일 약함
제약 · 예외  ███████░░░  18/25

잘한 것
  "너는 10년 차 B2B 마케터야" — 역할에 경력까지 붙여서 답변의 눈높이가 정해졌습니다.

아쉬운 것
  출력 형식이 비어 있습니다. "정리해줘"만으로는 AI가 3줄로 줄지 3장으로 늘릴지 알 수 없어서,
  받아보고 다시 시키게 될 확률이 높습니다.

팁
  · 구조와 분량을 같이 정하세요 — "표로"만으로는 표가 20행이 될 수 있습니다.
  · "간단히"는 형식 지시가 아닙니다. 숫자로 바꾸세요.

이렇게 쓰시면 90점대입니다
──────────────────────────────
(고쳐 쓴 프롬프트 전문)
```

## 규칙

- **잘한 것을 먼저 말합니다.** 60점짜리에도 잘한 구석은 있습니다. 찾아서 이름을 붙여줍니다.
- **아쉬운 것은 가장 큰 것 하나만** 깊게 다룹니다. 네 항목을 다 지적하면 아무것도 안 고칩니다.
- **고쳐 쓴 프롬프트 전문은 반드시 넣습니다.** 이게 이 명령어의 핵심입니다.
  설명만 주면 사용자가 "그래서 뭘 어떻게"를 다시 번역해야 합니다. 복사해서 바로 쓸 수 있어야 합니다.
- 고쳐 쓴 버전은 **원래 의도를 바꾸지 않습니다.** 더 좋은 아이디어를 끼워 넣지 마세요. 형식만 갖춰줍니다.
- 고쳐 쓴 프롬프트 뒤에 한 줄 덧붙입니다: "이 프롬프트를 다음에도 쓰시려면 `/save-prompt 이름`".
  반복 업무(상세페이지·CS·리포트)로 보이면 꼭 권하세요 — 저장·재사용이 연구가 확인한 실질 개선 경로입니다.
- 존댓말, 간결하게. 훈계하지 않습니다. 점수는 낙인이 아니라 다음 한 걸음의 방향 표시입니다.
