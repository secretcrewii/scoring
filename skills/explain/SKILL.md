# 쉬운 말로 다시 설명

AI가 작업을 끝내고 낸 보고가 너무 길거나 어려울 때, **다른 AI에게 물으러 가지 않고
그 자리에서 바로** 이해할 수 있게 풀어줍니다. 작업 흐름이 끊기지 않는 것이 목적입니다.

## 절차

1. **설명 대상 확보**
   - 인자로 특정 부분을 지목했으면 그 부분을 중심으로 설명합니다.
   - 비어 있으면 **직전 어시스턴트 응답**(이 명령어 바로 앞의 보고·설명)을 대상으로 합니다.
   - 직전 응답이 없으면 "어떤 내용을 풀어드릴까요?"라고 한 줄로 묻고 멈춥니다.

2. **눈높이 설정** — 읽는 사람은 개발 지식이 없는 대표(경영자)입니다.
   - 기술 용어는 쓰지 않거나, 쓰는 즉시 일상 비유로 풀어줍니다.
   - 코드·파일 경로·명령어의 나열은 "무엇이 어떻게 됐다"는 결과 중심 문장으로 바꿉니다.
   - 원래 보고에 없는 내용을 지어내지 않습니다. 원 보고가 모호한 부분은 모호하다고 말합니다.

3. **출력** — 아래 형식을 그대로 씁니다.

## 출력 형식

```
한 줄로 말하면
  ○○을 만들어서 이제 △△이 됩니다.

무슨 일이 있었나
  · (한 것 1 — 일상 언어로, 왜 필요했는지 포함)
  · (한 것 2)
  · (한 것 3 — 최대 5개, 사소한 건 묶어서)

지금 상태
  끝난 것: …
  남은 것: …

대표님이 정하실 것 / 하실 일
  · (결정이 필요한 것. 없으면 "지금은 없습니다 — 그냥 쓰시면 됩니다")

용어 한 줄 풀이 (원 보고에 어려운 용어가 있었을 때만)
  · 훅(hook): 특정 상황이 되면 자동으로 실행되는 장치. 알림 설정 같은 것.
```

## 규칙

- **비유는 회사 업무에서 가져옵니다.** 서버는 "창고", 배포는 "매장에 진열", 커밋은 "중간 저장",
  버그는 "불량", 테스트는 "검수" — 이커머스를 운영하는 사람이 바로 그려지는 그림으로.
- **결정이 필요한 것을 반드시 분리해서 보여줍니다.** 대표가 보고에서 진짜 알고 싶은 건
  "그래서 내가 뭘 해야 하는데?"입니다. 없으면 없다고 명시합니다.
- **원 보고보다 짧아야 합니다.** 풀어 쓴다고 길어지면 실패입니다. 절반 이하를 목표로.
- **숫자와 상태는 그대로 보존합니다.** "테스트 45개 통과" 같은 사실을 뭉개지 않습니다.
  실패·미완료가 원 보고에 있으면 숨기지 말고 "남은 것"에 그대로 적습니다.
- 설명 후 "더 궁금한 부분을 짚어주시면 그 부분만 더 풀어드릴게요" 한 줄로 마칩니다.
- 존댓말, 간결하게. 가르치려 들지 않습니다.
